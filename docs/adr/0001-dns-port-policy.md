# ADR-0001：DNS 端口与 Mihomo 同步策略

- **状态**：已接受
- **日期**：2026-10-03

## 背景

模块同时提供 AdGuard Home 明文 DNS 和可选的 TLS/DoH 服务，并可能维护 Mihomo 的 DNS 配置。明文 DNS 端口可以避免固定端口冲突，但 TLS/DoH 端点需要保持稳定；此外，Mihomo 配置中既有用户内容，也可能有模块历史写入的受管项。

## 决策

### 明文 DNS

`config.prop` 的 `random_dns_port` 默认值为 `yes`。

- `yes`：启动时随机化 AdGuard Home 的明文 DNS 端口，并同步更新 AGH-managed Mihomo DNS。
- `no`：不随机化；保留现有且有效的 `redir_port`，其缺失或无效时使用 `5591`。此模式不改写 Mihomo 配置。

### TLS/DoH 优先级

当 AdGuard Home 的 TLS 已启用且 `port_https > 0` 时，运行时使用一次性的覆盖策略：禁用明文 DNS 随机化，并禁止 Mihomo 写入。该覆盖只存在于运行时，不回写 `config.prop`。为移除旧版本留下的模块受管标记，首次执行一次清理是允许的；清理不应扩展为重写用户拥有的 Mihomo 配置。

TLS/DoH 端点保持固定，不参与明文 DNS 端口随机化。稳定端点是客户端配置、端点发现以及证书校验的契约；改变它会使已有客户端配置失效，且不能通过随机化明文端口获得同等收益。

## 范围与安全边界

本 ADR 只定义端口选择、运行时优先级和模块受管 Mihomo 项的边界。TLS 证书、私钥、订阅链接、令牌及其他秘密均不提交到仓库，也不作为示例配置或文档附件保存；部署者应通过设备本地或受保护的配置机制提供它们。

## 后果

- 默认安装可使用随机明文 DNS 端口，并保持 AGH 与受管 Mihomo DNS 的一致性。
- 选择固定端口时，用户已有的有效端口得到保留，且 Mihomo 配置不会被模块触碰。
- TLS/DoH 启用后，稳定的 HTTPS 端点优先于随机化策略；旧受管标记只允许做一次性清理。
- 端口策略不会自动携带或生成任何证书、私钥或其他秘密。
